# Ordinary handoff original-command outcome, v1

Operations 21 and 22 retain the original command UUID and the SHA256 of its complete protobuf request, including the idempotency key, original expiry and typed handoff action. No extra operation or remote capability is introduced. The existing `recovery.ordinary.v1` grant and default-off center channel remain required for admission.

The native write transaction creates private, create-only `recovery/commands/<command>.json` decisions. The main recovery journal links their exact SHA256 values. Preparation links a decision before committing `ORDINARY_PREPARED`. Execution persists `issued_command` before any unit action, then links the successful selected-check observation before publishing the immutable native receipt and committing `ORDINARY_ACTIVE_APPROVED_CHECKS`. Each handoff has at most two command decisions. Local handoffs omit the optional binding fields and retain their prior receipt format.

Receipt queries authenticate the original encrypted UNKNOWN admission and validate the command binding, linked decision, source and grant archives, and exact result shape. Execution additionally requires the committed native state, bound issued command, immutable receipt digest and schema-2 ready observation with all selected checks passed. Queries never call systemctl, a live business provider, recovery/repair, or receipt publication. Original command expiry does not invalidate a proven historical decision. Only the execution database receives the final receipt and one resolution row; concurrent queries preserve the first resolution.

Before a later legitimate recovery replaces a terminal bound handoff journal, its exact bytes are archived create-only as `<handoff>.ordinary-journal.json`. Subsequent queries can use that history without inferring anything from current units or current grants. A missing main recovery journal with retained command evidence blocks adoption, other managed writers, and agent/Core package lifecycle changes. Evidence remains in place.

Missing, unsafe, changed, unlinked, legacy or incomplete evidence leaves UNKNOWN. `RECOVERY_REQUIRED` cannot prove an execution result or release its write gate. An earlier preparation decision can remain provable without changing the later recovery-required state. A query never re-admits or replays a write.

Success adds `reconciliation.source=ordinary.handoff.journal.v1` with the original command ID, operation, full request digest, handoff ID, journal digest and decision digest. The center reconstructs the original encrypted wire request and validates this proof before accepting it; an UNKNOWN transition produces one `task.reconcile.ordinary_handoff` audit event. The bilingual task drawer explains the read-only proof and selected-check scope. `normalBootVerified` and `kuraRecoveryVerified` remain false.

The explicit process-loss harness is compiled only in test binaries. It exits after a successful native decision and before saving the execution receipt. Its fixture must be private and explicitly selected; production release binaries do not expose the harness. See the current console review and evidence for actual runtime coverage and deferred environments.
